# 합성 실행 과제 비교: 토큰은 감소했지만 시간은 거의 같았다

2026-11-15 KST에 네 합성 과제를 두 번씩 반복해 Web 우선과 OpenAkashic 우선을 총 16회 비교했습니다. 같은 `gpt-6.1-sol` medium과 native CLI, 도구, 격리 환경을 사용했습니다. 최종 전체 성공은 **OA 8/8, Web 5/8**이고 코드 검사는 양쪽 **8/8**, 총 **16/16** 통과했습니다. Web의 세 로컬 예산 종료는 코드가 통과했더라도 전체 실패로 남겼습니다.

양쪽이 모두 완전 성공한 **고정된 5/8짝**을 두 지표에 똑같이 사용했습니다. 이 집합에서 OA의 제공자 총 토큰 합계는 **14.26% 적었습니다**. 시간 합계는 **0.535% 짧아 사실상 같았습니다**. 시간 기하평균 비율의 기술적 부트스트랩 95% 구간은 **0.8648–1.1528**로 1을 포함합니다. 따라서 명확한 속도 향상이나 일반적인 효율 개선이 입증됐다고 말하지 않습니다. 5짝은 네 과제의 일부이며 반복 간 과제 의존성을 모델링한 추론이나 통계적 비열등성 검정도 아닙니다.

실패를 포함한 16회의 전체 제공자 총 토큰은 **2,990,143**이며 OA **1,379,458**, Web **1,610,685**입니다. 캐시 입력 **2,269,696**은 입력 **2,899,810**의 부분집합입니다. 입력과 출력 **90,333**을 한 번씩 합산했고, 실제 요금이나 청구서 절감은 확인하지 않았습니다. 모든 사용량은 완전한 제공자 영수증과 요청 해시 연결을 갖지만, 공개 묶음에는 원시 영수증과 응답 ID 대신 개수와 해시를 제공합니다.

두 독립 평가자가 익명 산출물을 검토했고 부모 검토자가 최종 조정을 남겼습니다. A09/A13은 검색과 검사가 같은 명령에 섞여 익명 패킷에서 검증 출력이 빠졌으므로, 원본의 검사 뒷부분과 마지막 재실행을 대조해 보충했습니다. 원래 두 검토와 보충 근거를 함께 공개합니다. 출처나 문체에 남는 조건 단서 때문에 완전한 블라인딩을 보장하지 않습니다. 검색 경로나 방법 인용 자체에는 품질 점수를 주지 않았습니다.

이 실험에는 사후 수정이 있습니다. 앞선 첫 시도는 일반 지침이 OA 질의로 들어간 연동 오류로 2/16회에서 중단했고, 그 두 실행과 미실행 14회를 별도로 보존했습니다. v2에서는 실제 과제 본문과 일반적인 질의 지침을 양쪽 초기 문맥에 똑같이 넣었습니다. 여덟 번째 실행의 로컬 예산 실패 뒤에는 이미 예약된 나머지 여덟 실행을 모두 진행하도록 제어기의 중단 정책만 수정했습니다. 실패를 재시도하거나 개별 한도를 늘리지 않았습니다. 첫 짝은 이미 노출됐고 중단 정책이 중간에 바뀌었으므로 탐색적 결과로 읽어야 합니다.

실제 중복 본문 캐시 적중은 **0회**였습니다. 별도 무모델 재생에서는 같은 SQLite v3 GET 응답을 같은 JSON 직렬화로 비교해 **18,851 → 12,475바이트**로 줄였고 최신 피드백을 보존했습니다. 이 클라이언트 동작 확인은 실제 모델 토큰, 시간이나 품질의 검증과 분리합니다.

본문, README와 코드 단계를 대조한 실제 방법 적용은 OA 여섯 실행의 일곱 방법 적용입니다. Kubernetes는 클러스터 없는 설정과 실패 횟수 모델, pandas는 합성 자료의 기술적 대안 비교입니다. SQLite의 성공도 쓰기 정지 과제에서 백업과 검사를 마친 범위에만 해당합니다. 실제 운영 복구나 동시 쓰기 중 정확한 시작 시점의 검증이 아닙니다. HTTP 두 실행은 보관 방법이 없어 공식 문서로 진행했으며 방법 적용 outcome으로 만들지 않았습니다. Web 실패도 미열람 방법의 outcome으로 붙이지 않습니다.

검색 수정은 [저장된 주제와 토픽에 따른 제한된 회수 정책](subject-topic-retrieval.md)입니다. 이 네 과제에서 관련 방법을 회수했다고 모든 질의의 의미 적합성이 해결된 것은 아닙니다. 추가 공개 QA에서는 pandas의 형식 변환이나 join처럼 같은 제품이지만 목적이 다른 질의에 관련성이 낮은 방법이 남았습니다. 실제 적용 전 전체 방법과 출처를 확인해야 하며, 이번 수정의 범위를 일반적인 제품별 의미 이해로 확대하지 않습니다.

[공개 검토 자료와 16회 전체 기록](../benchmarks/practical-efficiency-20261115/README.md)에는 과제, 검사, 실제 코드/README, 두 검토와 최종 조정, 해시와 조건을 담았습니다. 공개 산출물의 기능 검사는 격리 환경에서 다시 실행할 수 있지만, live 제공자와 브로커, 원시 trace/시스템 프롬프트, 인증/환경, 현재 DB/인덱스가 제외돼 원래 에이전트 실험 전체를 바로 재현할 수는 없습니다. 준비된 owner 피드백은 별도 검토 제안이며 실제 등록 영수증과 구분합니다.

[앞선 11월 14일 비교](practical-comparison-2026-11-14.md)는 Web 2/4, OA 1/4 성공과 OA 사용량 누락으로 전반적인 효율 개선을 입증하지 못했습니다. 그 기록과 이전 프로토타입의 토큰 증가 결과를 고치거나 이번 결과에 합치지 않았습니다.
