# 실행 과제 비교: 공개 재현 자료

같은 모델과 실행 환경에서 일반 웹 검색과 OpenAkashic 우선 검색을 비교한 4개 합성 과제, 총 8회 기록입니다. 실제 운영 장애나 사용자 업무 성과를 측정한 결과는 아닙니다. 독립 평가자가 익명 순서로 8개 산출물을 검토했지만 README에 검색 경로 단서가 남아 완전한 블라인딩은 아니었습니다. 평가자는 코드를 별도 실행하지 않았으며 동결된 실행 검사는 따로 기록했습니다. 이 묶음을 준비하며 새 모델 호출이나 공개 게시를 수행하지 않았습니다.

최종 전체 성공은 web 2/4, OA 1/4입니다. 평균 전체 시간은 web 183.80초, OA 197.59초였습니다. 실행 검사 통과는 web 4/4, OA 3/4입니다. CLI 정상 종료는 web 2/4, OA 1/4로 별개입니다. OA HTTP 과제는 시간 초과로 제공자 사용량이 불완전하므로 전체 토큰 증감률을 계산하지 않습니다. 모든 실패와 시간 초과를 8회 분모에 포함했습니다. summary.json의 완전한 사용량 쌍은 보조 자료이며 성공당 절감이나 일반 효용의 증거가 아닙니다.

비교 동결본에는 61개 방법이 있으며 58개 문서 기반 방법의 짧은 출처 인용 75/75개가 채워졌고 원문 위치 검사를 통과했습니다. 이는 방법의 효과를 입증하지 않습니다. 실제 관련 방법 본문을 읽은 과제는 SQLite입니다. Kubernetes와 HTTP에는 TanStack Query 방법이 부적합하게 추천됐고, pandas는 검색 결과가 없었습니다. 이후 공식 문서로 전환했습니다. 비교 동결본에는 Kubernetes와 pandas 관련 방법이 있었지만 해당 질의에서 미회수 또는 부적합 추천이 발생했으며, HTTP 표준 라이브러리 클라이언트는 원래 수집 범위 밖의 fallback 대조 과제였습니다. retrieval-coverage.json은 사후 로그 진단이며 평가 분모나 기준을 바꾸지 않습니다. Kubernetes 산출물이 통과했다고 OpenAkashic 방법 적용 성공으로 계산하지 않습니다.

제공자가 돌려준 입력/출력 카운터를 기록했지만 원시 SSE 해시와 응답 고유 ID가 없어 응답 식별을 독립적으로 완전히 검증하지 못했습니다. 캐시 입력은 이미 입력 토큰에 포함돼 있습니다. 요금이나 청구서 절감은 측정하지 않았습니다. CLI의 도구 정의, 문맥 재전송, patch 유틸리티 탐색 등의 비용도 포함되며 최소 구성 agent의 성능을 대표하지 않습니다.

v2의 초기화 실패와 v3의 예산 실패 및 중단은 prior-negative-cohorts.json에 남겼습니다. v4는 그 결과를 본 뒤 토큰 한도를 200k로 바꾸고 과제당 반복을 1회로 줄인 적응적 자원 보정 코호트입니다. 이전 코호트와 합산하지 않습니다.

검증:

    python3 verify_results.py

Docker에서 동결된 실행 검사를 다시 돌리려면 먼저 environment/에서 이미지를 만들고 지정합니다. 모델이나 인증은 사용하지 않습니다. 생성된 후보 코드의 실행은 네트워크와 호스트 접근이 차단된 컨테이너에 한정됩니다.

    docker build -t oa-practical-replay environment
    python3 verify_results.py --replay-checks --image oa-practical-replay

원래 사용한 이미지 ID와 의존성 버전은 provenance.json과 environment/에 있습니다. 재빌드 이미지는 같은 패키지 버전의 재현 환경이며 원래 이미지 바이트와 같다고 주장하지 않습니다. Kubernetes 검사는 정적 manifest 검사이며 실제 클러스터 검증이 아닙니다.

SHA256SUMS는 자기 자신을 제외한 모든 파일을 나열합니다. 후보 파일의 원본 해시와 공개 투영 해시는 candidate-artifact-provenance.json에서 구분합니다. 누락된 README나 코드 파일을 만들어 채우지 않았습니다. 원시 제공자 프롬프트와 trace, 인증·환경 정보, 개인 경로, 원문 전체는 포함하지 않았습니다.
